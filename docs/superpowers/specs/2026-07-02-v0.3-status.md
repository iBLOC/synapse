### Phase 4.4 — Lobe register endpoint (this session)
- **4.4a** `register_handler` was defined but never mounted in
  `api::build`. The 4 lobes posted to `{cortex_url}/register` and
  silently got 404 — no lobe ever appeared in `/shadow/v1/agents`.
  Root cause: the URL design was flat (`/register`) and didn't
  reflect the cortex namespace.
- **4.4b** New path: `POST /cortex/lobes/{name}`. The URL itself
  identifies the agent (e.g. `POST /cortex/lobes/occipital`),
  matching the 4-lobe anatomy (cortex = 大脑皮层, lobes = 4 大脑分区).
  Body carries `kind`, `url`, `agent_card`, and (optionally) `name`;
  when the body has `name` it must match the path (typo protection).
- **4.4c** DB upsert is now best-effort: on failure, log a warning
  and still update the in-memory cache so the lobe is routable.
  This makes `register` resilient to transient DB outages; the
  operator can re-register once the DB is back.
- **4.4d** `tests/lobe_register.rs` — 7 new e2e tests covering
  register, fetch-by-name, full-message-path-through-shadow,
  error paths (non-native / url-body mismatch / agent_card
  mismatch), and re-register. Also fixed `acquire_timeout(200ms)`
  on test lazy pools so failed upserts fail fast (default 6s
  timeout made one test run 60+ seconds).
- **4.4e** 4 lobes (memory, temporal, parietal, occipital) updated
  to `POST /cortex/lobes/{name}`.

## Architecture Decisions Locked

1. **A2A is the internal agent-to-agent protocol** between cortex and the
   4 lobes (and between lobes). v0.1 wire is the current default; v0.2
   wire via a2a-rs SDK is available and cortex's gateway translates
   between them.

2. **Shadow API is the external façade**. External clients (shadow-desktop,
   shadow-mobile, web UIs) talk to cortex via `/shadow/v1/*` only. The
   shadow API is REST + SSE — no A2A on the wire. The cortex translates
   shadow requests into `CortexA2AClient::send_task` calls.

3. **Modalities + capabilities are an AgentCard extension**. Synapse
   extends a2a-rs's `AgentCard` with `metadata.input_modalities`,
   `metadata.output_modalities`, `metadata.capabilities` so clients can
   introspect what each lobe accepts/produces.

4. **A2A does not carry WebRTC**. Real-time voice/video is out of scope
   for A2A v1.0 (only SSE-based server→client streaming). When needed,
   shadow API will grow a `/shadow/v1/media` endpoint that handles
   WebRTC handshake and forwards frames via custom binding (A2A's
   official position: no WebRTC/WebTransport in v1; only custom
   bindings for non-HTTP transports).

5. **Long-term memory lives in the hippocampus lobe** (the `memory`
   project). Shadow API's in-memory `ConversationStore` is a transient
   façade; persistent conversation history will be backed by the
   hippocampus once its `MemoryBackend` is implemented.

6. **Each lobe project loads its own WASM sub-agents**. The 4 大脑分区
   projects are self-contained — they depend on Synapse, not on cortex
   for runtime. Cortex's role is platform/registry, not runtime.

## What's NOT in v0.3 (deferred)

- **WASM agent loading by cortex**: `cortex/src/wasm/` is skeleton
  (`WasmManager`, `WasmBinaryStore` exist but no live loading).
  cortex→cortex lobe communication today uses the A2A gateway, not
  WASM module loading. The 4 lobes themselves are native binaries.

- **Prefrontal running as multi-agent supervisor**: `prefrontal/` is
  mature code with a `Supervisor` and a github-search sub-agent, but
  it isn't yet wired into cortex as a registered lobe. Adding it
  would let shadow route complex task-execution requests to
  prefrontal (which then dispatches to its sub-agents).

- **Cross-lobe routing test**: cortex→temporal→prefrontal chain is
  architecturally defined but not yet covered by an integration test.

- **WebRTC shadow media endpoint**: deferred until a concrete real-time
  voice/video use case arrives. The architecture leaves room for it
  (`/shadow/v1/media/...`); no implementation yet.
