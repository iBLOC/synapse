## 1. Project positioning (recap of project-boundary doc)

**Synapse** = foundation library (layer 2).
**Prefrontal**, and any future supervisor / cluster project (layer 3+).
**shadow-*** apps (layer 4).

Within Synapse we do:

- Streaming primitives (`StreamReader`, `AgentStreamEvent`)
- LLM provider abstractions (OpenAI / Anthropic over `wasi::http` and `reqwest`)
- A2A protocol wrappers around `a2a-rs` SDK
- WASM agent package format & runtime plumbing (`wasmtime`-based)

We do **not** do scheduling, supervision, persistence, axum serving,
auth, or UI.

Each agent WASM module exposes a fixed contract — the
**WASM Agent ABI** — that the supervisor invokes to route inbound
A2A calls and consume streaming events.

## 3. WASM Agent ABI

> Full reference: `docs/wasm-agent-abi.md`. Summary below.

### 3.1 Imports (host → WASM)
Synapse assumes the host provides:

- `wasi:http/outgoing-handler` — for outbound HTTP / SSE to LLM providers
- A custom `synapse:host/agent-config` with one export function `get_config(ptr, len) -> (ptr, len)` returning a JSON blob with: `llm_base_url`, `llm_api_key`, `llm_model`, `a2a_peers[]`
- A custom `synapse:host/a2a-call` with `send_to_peer(peer_id, msg_ptr, msg_len, out_ptr, out_len_ptr)` for outbound A2A peer calls (since a2a-rs client SDK is native-only; the host executes the call and returns the response)

### 3.2 Exports (WASM → host)
A Synapse-compiled agent MUST export:

| Symbol | Type | Purpose |
|---|---|---|
| `agent_card` | `(out_ptr: i32) -> i32` (writes `AgentCard` JSON, returns length) | A2A discovery |
| `stream_run` | `(input_ptr: i32, input_len: i32, out_handle_ptr: i32) -> i32` | Yield a stream handle for inbound `message/send` or `message/stream` calls |
| `cancel_run` | `(handle: i32) -> i32` | Cancel a running stream by handle |
| `query_task` | `(task_id_ptr, task_id_len, out_ptr) -> i32` | Return current task state for `tasks/get` |
| `subscribe_task` | `(task_id_ptr, task_id_len, out_handle_ptr) -> i32` | Subscribe to task events (server push / resubscribe semantics) |

Streaming via **shared linear memory**: agent writes `AgentStreamEvent`
records into a host-provided ring buffer; host polls the buffer when
reading the agent's outbound stream response.

### 3.3 Memory model

- WASM owns linear memory.
- Exports take `(ptr, len)` for input strings and a pointer where the
  agent may write responses.
- Host pre-allocates one buffer (default 64 KiB) per stream handle for
  outbound `AgentStreamEvent` payloads.
- ABI version stamp: each WASM image exports a `synapse_abi_version`
  function returning a u32; current target is `1`.

## 4. A2A integration

### 4.1 Server side
- `a2a-rs` v0.4 (`a2a-server-lf`) provides `DefaultRequestHandler` +
  `AgentExecutor` (a 2-method trait).
- Synapse provides `SynapseAgentExecutor` that implements `AgentExecutor`
  and bridges events to **whatever WASM-side execution model the
  supervisor decides** (typically: instantiate a runtime, look up the
  WASM module by ID, invoke its `stream_run` export).

### 4.2 Client side
- `a2a-rs` v0.2 (`a2a-client-lf`) provides `A2AClient<T: Transport>`
  with `A2AClientFactory` for protocol negotiation.
- **Important**: client SDK only has native transport. Synapse wraps
  client usage at the supervisor boundary — within WASM, peer calls
  go through the `synapse:host/a2a-call` import (defined in 3.1) which
  the supervisor fulfills via the native `A2AClient`.

## 6. Configuration injection

To honor "support 传入 LLM API 地址等信息" (externalized config):

- Each agent WASM at startup calls `host::get_config(...)`.
- The host supplies:
  - `llm_base_url` — e.g. `https://api.openai.com/v1`
  - `llm_api_key` — runtime secret, never baked into WASM
  - `llm_model` — e.g. `gpt-4o`
  - `llm_extra` — provider-specific overrides (org ID, project, etc.)
  - `a2a_peers` — list of `(name, url)` for outbound peer discovery
- Synapse provides a `synapse-agent-config` JSON schema + serde impl
  so the configuration round-trips cleanly.

## 8. Out of scope for v0.2

- Persistent task stores (sqlite/postgres) — `InMemoryTaskStore` only.
- Auth implementations (OAuth2/API-key) — `CallInterceptor` hook exposed.
- WASM-side A2A client — peer calls go through host import.
- Multi-region A2A — supervisor concern.
