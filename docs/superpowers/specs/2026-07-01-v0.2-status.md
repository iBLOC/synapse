## Breaking changes

| Change | Reason | Migration |
|---|---|---|
| MSRV 1.75 → **1.85** | Required by `a2a-rs` | Run `rustup update 1.85.0` |
| Edition 2021 → **2024** | Required by `a2a-rs` | `cargo fix --edition` |
| `BaseChatModel::http` field type: `Arc<dyn HttpClient>` → `Arc<dyn HttpClientSse>` | So providers can `sse_post` | Construction sites that held the old type |
| `reqwest` 0.12 → 0.13, `axum` 0.7 → 0.8 | Match `a2a-rs` versions | Update lockfile |

## What downstream (Prefrontal) needs to do

1. Pull `synapse = "0.2"` once we tag a release (currently on the
   `feat/streaming-a2a` branch).
2. Implement a `WasmModule`-backed supervisor that compiles to one
   synapse-per-agent; follow `docs/wasm-compilation-guide.md` for the
   build pipeline.
3. For each loaded agent, instantiate a `SynapseAgentExecutor` and feed
   it into a `DefaultRequestHandler`. Wire the resulting
   `axum::Router` to the supervisor's HTTP listener — same pattern as
   `src/a2a/server.rs::A2AServerBuilder`.
4. For outbound peer calls from inside an agent WASM, provide a
   `synapse:host/a2a-call` import that delegates to
   `synapse::a2a::client::A2AClient`. The host impl lives in
   Prefrontal; the ABI is documented in `docs/wasm-agent-abi.md`.

## What still needs decisions before tagging v0.2

1. **MultiAgent supervisors**: keep as reference (delete later), or
   delete now? Recommended: keep until at least Prefrontal v0.1 ships,
   so users migrating from "in-process supervisor" to "WASM cluster"
   have a known starting point.
2. **`synapse::a2a::translate` module split**: cosmetic; defer.
3. **Auth mapping on `AgentCard`**: depends on whether `a2a-rs` 0.4.x
   changes — track upstream before adding.
4. **WASM CI**: pin a toolchain config and a `cargo check
   --target wasm32-wasip2` step so we don't regress the WASM target.
