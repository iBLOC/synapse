# Synapse Family — v0.3 Architecture

> **Status**: Draft v0.3 — supersedes v0.2 scope.
> Major pivot (2026-07-01): **Synapse is the agent development
> framework (脚手架)**. The 4 大脑分区项目 are multi-agent
> systems built ON TOP of Synapse. Cortex is the platform that
> aggregates them.

## 0. What an agent is

> "Agent = LLM + skill + MCP + prompt 的组合"

A Synapse agent is a single Rust binary that combines:

- **LLM** — talks to cortex's embedded neure (or any OpenAI-compat API)
- **Skills** — local Rust functions the agent can call
- **MCP** — Model Context Protocol tools (e.g. github MCP)
- **Prompt** — system prompt that tells the agent its job

The **agent is self-aware**: it knows which skills/MCPs to use for
which task, because the prompt + skill registry are pre-configured at
build time. The agent does NOT need a supervisor to tell it "use
github MCP for github tasks" — that's baked in.

## 0.1 Why WASM is Synapse's advantage

A Synapse agent is compiled to `wasm32-wasip2` and runs in a
sandboxed WASM runtime inside the supervisor. The supervisor (cortex
or prefrontal) loads the `.wasm`, provides LLM/MCP/skill plumbing
via the [WASM Agent ABI](./wasm-agent-abi.md), and the agent runs
in isolation. The supervisor is the OS; the agent is the process.

This means:
- A user can swap agent implementations without touching the host
- A bug in one agent can't take down the others
- WASM image is portable: same `.wasm` runs in prefrontal, cortex,
  shadow-desktop, or shadow-mobile

## 1. The 4 大脑分区项目 are multi-agent systems

Each is a **standalone multi-agent system project**, built on
Synapse, that demonstrates a different pattern of multi-agent
coordination. They are not "special abstraction layers" — each is
just a Synapse project with its own `Cargo.toml`, its own agents,
its own supervisor logic.

| Project | Pattern | What it shows |
|---|---|---|
| **`temporal/`** (颞叶) | **User-channel multi-agent** | The user's voice/text surface. Routes user messages to other lobes / prefrontal. |
| **`prefrontal/`** (前额叶) | **Task-execution multi-agent** | Supervisor + sub-agents. Demonstrates the github-MCP sub-agent pattern. |
| **`parietal/`** (顶叶) | **Sensory-data multi-agent** | IoT / sensor stream ingest. Anomaly detection. |
| **`occipital/`** (枕叶) | **Vision multi-agent** | Camera/image stream. Face recognition. Object detection. |
| **`memory/`** (海马体) | **Long-term-memory multi-agent** | Vector store, knowledge graph, episodic memory. |

Each is just a `cargo new` style project that **depends on Synapse**.
The 4 projects are siblings of `synapse/`, `cortex/`, `neure/`.

## 2. Concrete example: github research task

The user's mental model from the chat, made concrete:

```
user → shadow-mobile
       "research the synapse project on github"

       ↓

temporal lobe (user-channel multi-agent)
  ├─ receives the message
  ├─ recognizes this is a research task
  └─ creates A2A task → prefrontal lobe

       ↓

prefrontal lobe (task-execution multi-agent)
  ├─ supervisor agent receives the task
  ├─ breaks into sub-tasks:
  │   - "find synapse-rs/synapse on github"        → github-search sub-agent
  │   - "summarize recent commits"                  → git-insights sub-agent
  │   - "extract README highlights"                 → doc-extract sub-agent
  └─ dispatches sub-tasks to sub-agents in parallel

       ↓

github-search sub-agent (running in WASM)
  ├─ prompt: "you are a github code search specialist"
  ├─ skills:  ["read_file", "search_code", "list_issues"]
  ├─ mcp:     github MCP server (preset in the WASM image)
  └─ knows:   "to answer github questions, use the github MCP"
            (this knowledge is BAKED INTO the prompt at build time)

  → returns: A2A reply with search results

       ↓

prefrontal supervisor aggregates
       ↓

temporal formats reply and sends to shadow-mobile
       ↓

user sees the answer
```

The key insight: **the github sub-agent doesn't need a supervisor to
tell it to use github MCP**. Its prompt + tool registry (preset at
build time) already encode that knowledge. The agent is a
self-contained, well-configured piece of code.

## 4. The 4 大脑分区 project shapes

Each project looks roughly like:

```
temporal/                    prefrontal/                  parietal/
├── Cargo.toml               ├── Cargo.toml              ├── Cargo.toml
├── src/                     ├── src/                    ├── src/
│   ├── main.rs              │   ├── main.rs             │   ├── main.rs
│   ├── agents/              │   ├── supervisor/         │   ├── sensors/
│   │   ├── greeting.rs      │   │   └── mod.rs          │   │   └── mqtt.rs
│   │   └── router.rs        │   ├── sub_agents/         │   └── anomaly.rs
│   └── a2a/                 │   │   ├── github.rs       └── a2a/
│       └── handlers.rs      │   │   └── git_insights.rs     └── handlers.rs
└── tests/                   │   └── a2a/
                             │       └── handlers.rs
                             └── tests/
```

But the **shape inside** is the same as any Rust project. Each
project is a multi-agent system that:
- Compiles to native + WASM
- Has its own supervisor
- Defines its own sub-agents as WASM modules
- Talks A2A to peers

## 5. What each project depends on (Cargo.toml)

```toml
[dependencies]
synapse = { path = "../synapse" }      # the framework
tokio = { ... }
serde = { ... }
a2a-rs client = ...                   # if talking to peers
# the project can also pull in:
mcp = "..."                            # MCP SDK
candle-core = "..."                    # local ML if needed
```

Cortex is the **only** project that path-depends on `neure` (to embed
it). The 4 lobe projects depend on **cortex's HTTP API** at
`/neure/v1/chat/completions` for LLM access — they don't link neure.

## 6. Where each agent lives

| Layer | Where it runs | Who builds it |
|---|---|---|
| Synapse (this project) | n/a — it's a library/framework | Synapse maintainers |
| An individual agent | Compiled to `.wasm`; loaded by cortex's WASM runtime | Whoever wants a custom agent |
| A 4 大脑分区 project's sub-agents | Compiled to `.wasm`; loaded by the project's own supervisor | The 4-project maintainers |
| The 4 大脑分区 project itself | Native binary hosting an axum HTTP server with A2A | The 4-project maintainers |
| cortex | Native binary; embeds neure in-process; loads WASM agents | Cortex maintainers |

## 7. Cortex's role: the platform

Cortex is the **platform** that:

1. **Embeds neure** so all lobes (and shadow-*) share one LLM endpoint
2. **Hosts hippoCampus (memory)** so all lobes share memory
3. **Loads WASM agent packages** at runtime via `synapse::wasm::WasmRuntime`
4. **Routes A2A** between shadow-* and the 4 lobes, and between lobes
5. **Tracks state** in Postgres (per `cortex/src/state.rs`)

The 4 大脑分区 projects don't talk to each other directly — they all
go through cortex. cortex owns:
- LLM provider config (single source of truth)
- Agent lifecycle (load / unload / health)
- Memory (single source of truth)
- Authentication / multi-tenant

## 8. The agent template

`synapse/templates/agent/` is the **only** template a lobe developer
needs. They use it to create new sub-agents inside their 4-project:

```bash
# Inside prefrontal/, add a new sub-agent:
cp -r ../synapse/templates/agent agents/github_search/
# Edit agents/github_search/src/lib.rs:
#   - System prompt
#   - MCP config (github)
#   - Skills the agent has
#   - Output format

# Build:
cd agents/github_search
cargo build --release --target wasm32-wasip2

# prefrontal's supervisor auto-loads the resulting .wasm.
```

This is the **same `templates/agent/` we already have** — the
template is correct, we just stopped calling it "agent template for
the synapse framework" and started seeing it as "agent template for
ANY multi-agent system built on Synapse".

## 11. Decisions still open

1. **Memory persistence**: cortex (Postgres) vs dedicated memory lobe
   (postgres + vector store). The user originally said cortex
   "implements 模型提供商管理" — but memory is a separate lobe
   (hippoCampus). Decision: memory is its own lobe, but cortex
   caches frequently-used memory lookups.
2. **A2A custom methods** (e.g. `memory/recall`): does a2a-rs v0.4
   support custom JSON-RPC methods, or do we need an "extension"
   protocol layer?
3. **WASM agent loading in cortex vs in each lobe**: cortex
   loads all agents centrally, or each lobe loads its own
   sub-agents locally? Recommended: each lobe loads its own
   sub-agents (so lobe projects are self-contained), cortex
   just routes A2A to them.
