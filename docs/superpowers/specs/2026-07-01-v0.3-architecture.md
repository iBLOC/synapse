# Synapse Family — v0.3 Architecture: Multi-Lobe Agent System

> **Status**: Draft v0.3 — supersedes v0.2 scope. Major pivot
> from "single agent framework" to "ecosystem of cooperating
> agent projects" coordinated by Cortex.

## 0. v0.3 pivot — what changed

| v0.2 (2026-07-01) | v0.3 (2026-07-01) |
|---|---|
| One Synapse crate, one agent concept | **One Synapse crate, five specialized agent projects** |
| Prefrontal is the cluster layer | Prefrontal stays the cluster layer; cortex orchestrates 4 native "lobe" agents + user-installed WASM agents |
| LLM providers (OpenAI / Anthropic) are peer libraries | All agents converge on **standard OpenAI API** for portability |
| Neuron is bundled with prefrontal | **Neuron extracted to its own project**, registers directly with shadow-desktop/mobile |

## 2. The four lobes

Each lobe is a **standalone Rust binary** that exposes an A2A
v1.0 server (using `synapse::a2a::server::A2AServerBuilder`).
Cortex discovers them at startup and routes inbound A2A calls.

### 2.1 颞叶 (Temporal lobe) — `temporal/`

Conversational agent. The user-facing voice/text surface.

| Capability | Description |
|---|---|
| Voice/video input | Receive audio/video from shadow-* via A2A `message/send` with media parts |
| Speech-to-text | Internal pipeline; depends on LLM API audio support |
| Speech emotion recognition | Plugin via OpenAI-style multimodal models; emits emotion-tagged events |
| Text reply synthesis | Standard OpenAI chat completions |
| Dispatches to prefrontal | When task needs execution, calls prefrontal's A2A endpoint |
| A2A surface | `message/send` (sync), `message/stream` (text/voice stream) |

**A2A peers**:
- → prefrontal (executes tasks)
- ← cortex (user messages routed in)
- ← parietal (sensory data, replies back to user)
- ← occipital (vision results, replies back to user)

### 2.2 顶叶 (Parietal lobe) — `parietal/`

IoT / sensor-data agent. Senses the world around the user.

| Capability | Description |
|---|---|
| MQTT / WebSocket / Modbus / etc. | Multiple IoT protocol adapters (plugin) |
| Time-series storage | Local ring buffer + Cortex push |
| Pattern detection | Anomaly events trigger downstream tasks |
| Dispatches to prefrontal | Anomaly or threshold event → prefrontal task |
| Reports to temporal | Streaming sensory feed → temporal for user awareness |

**A2A peers**:
- → prefrontal (tasks)
- → temporal (user-facing stream)

### 2.3 枕叶 (Occipital lobe) — `occipital/`

Vision agent. Processes image/video streams.

| Capability | Description |
|---|---|
| Camera / video input | Subscribe to shadow-* camera streams or pull from URL |
| Face recognition | Local model (dlib / ONNX); emits `FaceMatch { id, confidence }` events |
| Object detection | Optional, via OpenAI vision API or local model |
| Visual knowledge graph | Stored in `hippocampus` (memory project) |
| Dispatches to prefrontal | Recognition or detection events → prefrontal task |
| Answers temporal | "Who is this person?" queries return the matched identity |

**A2A peers**:
- → prefrontal (tasks)
- → temporal (identity answers)
- → hippocampus (knowledge graph read/write)

### 2.4 海马体 (Hippocampus) — `memory/`

Long-term memory. Stores user context, knowledge graphs, and visual
relationships.

| Capability | Description |
|---|---|
| Embedding storage | Vector store (sled / sqlite-vec / pgvector) |
| Knowledge graph | Triple store (subject, predicate, object) |
| Visual memory | Face embeddings + encounter history |
| Episodic memory | Event log with timestamps |
| A2A surface | `memory/recall`, `memory/store`, `memory/link` (custom methods) |

**A2A peers**:
- ← occipital (visual knowledge graph read/write)
- ← temporal (user context recall)
- ← prefrontal (agent state persistence)
- ← parietal (sensor history)

## 3. Neure — the LLM provider

**`neure` is its own project** (`/home/ibloc/Projects/neure/`), not a
built-in module. It is a layer-2 engine that already exists in the
codebase (see `neure/AGENTS.md`) and provides the full
OpenAI-compatible surface plus TTS / ASR / Rerank / Embedding
endpoints.

Cortex **embeds neure in-process** via a path dependency
(`neure = { path = "../neure" }`) and mounts neure's axum router
under `/neure/...` on its public HTTP surface. Shadow apps and the
4 lobes hit cortex at `/neure/v1/chat/completions` (etc.); they
never import neure directly.

```
shadow-desktop ─┐
                ├─→ cortex (public HTTP) ─→ neure (embedded, in-process)
shadow-mobile ──┤     │
                │     └─→ /neure/v1/chat/completions   (chat)
                │     ├─→ /neure/v1/audio/speech       (TTS)
                │     ├─→ /neure/v1/audio/transcriptions (ASR)
                │     ├─→ /neure/v1/rerank            (rerank)
                │     └─→ /neure/v1/embeddings         (vector)
temporal ────────┤
parietal ────────┤
occipital ───────┤
memory ─────────┘
```

### 3.1 Cortex's neure integration

`cortex::neure_embed` (in `cortex/src/neure_embed.rs`) wraps
`neure::run_embedded` and provides:

- `start_neure(port, config) -> NeureEmbed` — start the embedded runtime
- `NeureEmbed::router()` — the axum router to nest under any prefix
- `NeureEmbed::shutdown()` + `NeureEmbed::join()` — graceful drain

`CORTEX_SKIP_NEURE=1` disables embedding (CI / Postgres-only envs).

### 3.2 What this means for prefrontal

`prefrontal` previously called neure through `prefrontal::neure_adapter`.
With v0.3, prefrontal can either:
- (a) keep using `neure_adapter` directly (if running standalone,
  outside cortex), or
- (b) go through cortex's `/neure/v1/...` endpoints (if running
  under cortex orchestration)

Both paths are supported. The user does not need to migrate
prefrontal immediately.

## 4. Communication patterns

### 4.1 Voice/text user query (颞叶 flow)

```
user → shadow-mobile → temporal (A2A message/send, voice or text)
       temporal (emotion + intent)
       ├→ prefrontal: "execute task X" (A2A)
       │   prefrontal (agent dispatch, returns result)
       │   temporal (formats for voice output)
       └→ user (via shadow-mobile)
```

### 4.2 "Who is this person?" (颞叶 ⇄ 枕叶)

```
user → shadow-mobile → temporal
       temporal (text question)
       → occipital (A2A: "identify face in this frame")
          → hippocampus (face embedding match)
          ← hippocampus (matched identity)
       ← occipital (Person { name, last_seen })
       ← temporal (formats response)
       → user
```

### 4.3 IoT anomaly (顶叶 flow)

```
sensor → parietal
        parietal (anomaly detection)
        → prefrontal (A2A: handle anomaly)
        ← prefrontal (action plan)
        → temporal (a11y: "Heater turned off, returning to normal")
        → user
```

## 5. Synapse's role in v0.3

Synapse stays the foundation. Each lobe is a Rust binary that
**depends on synapse** for:

- `synapse::a2a::server::A2AServerBuilder` — host an A2A server
- `synapse::a2a::client::A2AClient` — call peer agents
- `synapse::stream::StreamReader<T>` — cancellation-aware streams
- `synapse::components::model` — OpenAI-compatible providers
- `synapse::wasm` — embed user-installed WASM agents (lobe users
  can install third-party agents into their lobe)

What synapse does **not** do in v0.3:
- Know about the lobe concept (cortex's concern)
- Define LLM routing (neuron's concern)
- Persist any state (memory's concern)

## 7. Open questions before tagging v0.3

1. **Lobe project structure**: should each lobe be a `templates/lobe/`
   scaffold inside synapse (one template, four projects copy it) or
   should synapse expose a `synapse-lobe` SDK crate that lobes depend on?
2. **Neuron's blast radius (revised)**: how much prefrontal code
   moves into cortex's built-in provider module? Need a precise diff.
3. **A2A custom methods** (e.g. `memory/recall`) — does a2a-rs v0.4
   support custom JSON-RPC methods, or do we need an "extension"
   protocol layer?
4. **Lobe discovery**: does cortex read a static config of lobe URLs,
   or does each lobe register itself with cortex at startup?
5. **WASM agents in lobes**: a user adds a third-party WASM agent
   via temporal's UI. Is the WASM runtime inside temporal, or does
   temporal delegate to cortex?
